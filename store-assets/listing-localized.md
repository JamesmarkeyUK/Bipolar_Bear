# Localised App Store / Play Store listing copy

Paste-ready translations of `listing.md` for the three largest markets among
the app's supported locales: **Spanish (es), French (fr), German (de)**.

Draft copy — have a native speaker skim the voice before submitting. Character
counts are noted for the fields Apple limits tightly (they count Unicode
characters, so accented letters = 1). App **names stay as the brand**
("Bipolar Bear" / "Bipolar Anonymous") — don't translate them.

Store-listing language ≠ in-app language: these go into App Store Connect
(add a Localization per language) and Play Console (Main store listing →
Manage translations). See the note at the bottom about the iOS "Languages"
field for a Capacitor app.

# Notes

- **URLs** (Support / Marketing / Privacy Policy) are the same for every locale —
  copy them from `listing.md`. The privacy page itself is now localised in-app,
  but the App Store/Play URL fields just take the one `https://www.bipolarbear.app/privacy.html`.
- **Screenshots** can be localised per language (App Store Connect + Play let you
  upload a set per locale). For a first pass, reuse the English screenshots in
  `store-assets/out/` — the store doesn't require localised images.
- **App Privacy / Data Safety** answers are the same across locales — fill them
  from the table in `listing.md`.
- **iOS "Languages" field (Capacitor caveat):** because the app is localised in
  JavaScript, not with native `.lproj` bundles, the App Store won't auto-detect
  es/fr/de/… as supported languages. To have them shown, add a
  `CFBundleLocalizations` array (all 10 locale codes) to the app's `Info.plist`
  in Xcode, and/or rely on the localised listings above (which is what actually
  drives search visibility).
- **The other 6 locales (it, pt, nl, pl, sv, zh):** not drafted here — say the
  word and I'll extend this file to cover them in the same format.
